# LLM の学習過程 — 事前学習と事後学習の方法まとめ

> 用語整理メモ。SFT / RLHF などの手法が「事前学習」「事後学習（=いわゆる "自己学習"・ファインチューニング）」のどこに当たるかを、フローと分類で整理する。本プロジェクト（LLM Science Exam, DeBERTa-v3 backbone）との接点も末尾に記す。
>
> ※ スコアを扱わない一般知識メモのため、`knowledge/README.md` の R1–R5（スコア考察規約）は非該当。

---

## 1. 全体フロー

```
[1] 事前学習                 [2] 事後学習 (= "自己学習" / ファインチューニング)
 Pre-training        ─→     ┌─ [2a] SFT ─→ [2b] 選好最適化 (RLHF / DPO) ─┐
                            └──────────────── チューニング段階 ────────────┘
       ↓                                       ↓
  汎用な基盤モデル                         指示に従う実用モデル
 (Base / Foundation)                      (Instruct / Chat モデル)
```

- **事前学習** = 土台づくり（1 回・超大規模）。知識のほとんどをここで獲得。
- **自己学習（事後学習）** = 仕上げ。**SFT が入口**、その後 **RLHF/DPO** で人間の好みに合わせる。
- **SFT は事後学習の最初のステップ**であり、事前学習には含まれない。

### 開発フローのイメージ

```
生テキスト数TB
   │  (1) 事前学習 …… 数週間〜数ヶ月・大規模GPU
   ▼
Base モデル（賢いが指示に従わない）
   │  (2a) SFT …… 数千〜数万件の指示応答ペア・比較的軽量
   ▼
SFT モデル（指示には従うが好みのズレ・不適切回答あり）
   │  (2b) RLHF / DPO …… 選好データで微調整
   ▼
Instruct / Chat モデル（ChatGPT のような最終形）
```

## 2. 各ステップの中身と分類

| 順 | ステップ | 手法名 | 使うデータ | やること | 分類 |
|---|---|---|---|---|---|
| 1 | 事前学習 | Pre-training | 大量の生テキスト（ラベルなし） | 「次の単語予測」等で言語・知識を獲得 | **事前学習** |
| 2a | 教師ありFT | **SFT** | 「指示 → 理想の回答」ペア（人手作成） | 指示に従う・望ましい形式で答える型を仕込む | **事後学習（自己学習）** |
| 2b | 選好最適化 | RLHF / DPO / RLAIF | 「どちらの回答が良いか」の選好データ | 人間の好みに沿って自然・安全・有用に磨く | **事後学習（自己学習）** |

> 補足: 2 の前後に「継続事前学習（特定ドメインの生テキストを追加学習）」を挟むこともあるが、これは性質上 **事前学習側** に分類される。

### どれが事前学習 / 自己学習か（早見表）

| 手法 | 事前学習 | 自己学習（事後学習） |
|---|:---:|:---:|
| Pre-training（次単語予測） | ✅ | |
| 継続事前学習 | ✅ | |
| **SFT** | | ✅ |
| RLHF | | ✅ |
| DPO | | ✅ |

## 3. 事前学習の「具体的手法」（目的関数で分類）

事前学習＝ラベルなしテキストでの自己教師あり学習。**何を予測させるか（目的関数）**で手法が分かれる。

| 手法 | 代表モデル | やること | 向くタスク |
|---|---|---|---|
| **自己回帰（CLM）** Causal LM / 次単語予測 | GPT 系, Llama | 左から順に「次の単語」を予測 | 文章生成（今の主流） |
| **マスク言語モデル（MLM）** | BERT, **DeBERTa** | 文中の一部を隠して穴埋め予測 | 文の理解・分類・抽出 |
| **Seq2Seq / Span 復元** | T5, BART | 欠損した範囲を復元・変換 | 要約・翻訳・変換系 |
| **置換トークン検出（RTD）** | ELECTRA | 「すり替えられた単語」を判定 | 高効率な理解系学習 |

### 事前学習を支える要素技術

| 区分 | 具体例 | 役割 |
|---|---|---|
| アーキテクチャ | Transformer（Decoder-only / Encoder-only / Enc-Dec） | モデルの骨格 |
| トークン化 | BPE, SentencePiece, WordPiece | テキストを単語片に分割 |
| データ前処理 | 重複除去, フィルタリング, 品質スコアリング | 学習データの質を担保 |
| 効率化技術 | Mixed Precision, FlashAttention, ZeRO/FSDP | 大規模学習を現実的なコストで回す |
| 位置表現 | RoPE, ALiBi, 学習可能位置埋め込み | 系列内の位置情報を与える |

### イメージ（自己回帰の場合）

```
入力:  「東京 は 日本 の ___」
            ↓ モデルが次を予測
予測:  「首都」
→ これを数兆トークン分くり返し、言語・知識・推論の土台を獲得
```

## 4. 事後学習（自己学習）の主な手法

| 手法 | 略称 | 内容 | 目的 |
|---|---|---|---|
| 教師ありFT | **SFT** | 「指示 → 理想の回答」ペアで学習 | 指示に従い、望ましい形式・口調で答える |
| 人間フィードバック強化学習 | RLHF | 報酬モデル＋強化学習で選好を反映 | 自然・安全・有用な回答に整える |
| 直接選好最適化 | DPO | 報酬モデルを介さず選好ペアで直接最適化 | RLHF を軽量化（実装が簡単・安定） |
| AI フィードバック | RLAIF | 人間の代わりに AI が選好を付与 | アノテーションコスト削減 |

---

## 5. 本プロジェクトとの接点

- 本コンペ（LLM Science Exam）の backbone **DeBERTa-v3** は **MLM 系（理解タスク向け）** の事前学習モデル。GPT 系の CLM とは目的関数が異なる。
- Cycle 01 で行っている MCQ 用のファインチューニングは、分類タスクへの **教師ありファインチューニング**（広義の事後学習）に相当。チャット用 SFT/RLHF とは目的が違うが、「事前学習済みモデルを下流タスクに適合させる」点で同じ事後学習の系譜。

## 用語注

- **「自己学習」** … 本メモでは一般的な **事後学習 / ファインチューニング** の意味で用いる。
- **「Self-Training」**（モデル自身の出力を疑似ラベルにして再学習する半教師あり学習）は別系統の概念。混同に注意。
- **「STF」** は綴り誤りで、正しくは **SFT (Supervised Fine-Tuning)**。
